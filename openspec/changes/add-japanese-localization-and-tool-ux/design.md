# Design

## Context

动机见 `proposal.md`；行为约束见两份能力规范。

- 现有页面由 Hono JSX、英文首页 HTML 模板和工具 HTML/内联脚本混合组成。`src/i18n/index.ts` 使用静态及脚本文本替换生成中文；共享导航、页面标题和 SEO 中还存在英文/中文二选一分支。
- `src/site.ts` 的全球配置启用 `en`、`zh`；中国配置只启用 `zh`。路由按配置挂载，VPS 静态构建使用中国配置。
- sitemap XML 按配置生成，但 TXT sitemap 和 `scripts/verify-seo.ts` 仍固定列举英文、中文。页面共 17 个，文档由独立路由提供。
- 首页已在 URL 中保存部分参数。其他工具及语言菜单尚未完整保存查询、片段和输入。首页与流动图的颜色解析会过滤非法条目；工具复制备用方法未确认返回结果；部分异步更新缺少过期响应保护。
- 外部 API 契约由 `src/contracts/colors-api.ts` 提供，API 服务不在本仓库。现有测试主要验证 HTML、路由、元信息及内联脚本语法。

## Goals / Non-Goals

**Goals:**

- 在现有渲染结构中建立明确的语言描述与类型完整的文案表，减少新增语言时遗漏动态反馈的可能。
- 共享复制、工具状态和异步结果管理，让同类问题在首页和工具页采用相同处理方式。
- 先形成稳定的默认流程，再逐项恢复高级功能；主操作无需先理解 API。
- 将契约校验与浏览器操作验证分开，回归测试可以控制响应顺序及失败条件。

**Non-Goals:**

- 不迁移框架、不引入浏览器端翻译服务、不增加服务端会话或用户账号。
- 不改动外部 API 参数或独立 offline-tools 应用；不新增自动判别输入格式或日文 CSS 名称别名库。
- 本变更不增加新的统计服务，不将有限的日本访问样本作为增长承诺。

## Decisions

### 1. 配置驱动的语言描述

扩展 `Locale` 为 `en | zh | ja`，建立统一描述表，包含语言自称、HTML lang、hreflang、Open Graph locale 和字体规则。全球配置启用三种语言，中国配置保持中文。共享布局、导航、反馈链接、转换标题和 SEO 使用该表，消除二选一分支。显式语言 URL 优先，不增加自动重定向。

备选方案是逐处增加三元分支；新增语言会继续依赖人工寻找所有分支，因此采用统一描述表。现有无前缀页面与重定向保留。

### 2. 文案使用键，机器值保持契约来源

在 `src/i18n/` 中按公共导航、首页、各工具和 SEO 划分有类型约束的文案。三个语言必须覆盖同一组键；动态脚本直接读取序列化的对应语言消息，插值通过命名参数完成。主题、效果和预设以契约中的稳定 ID 查询显示标签，请求仍使用原 ID。

首页保留 HTML 模板结构，将可见文本替换为明确的文案占位符；工具渲染使用文案键。受本变更影响的脚本文字全部迁移到消息表，停止依赖英文子串替换。可保留未涉及页面的受限兼容替换，但日文覆盖不得依赖替换顺序。脚本 JSON 转义 `<` 等敏感字符；HTML 内容和属性按各自上下文转义，动态列表使用安全文本节点。输出片段中用户输入需按 HTML/Markdown 等格式正确编码。

备选方案是复制整份日文模板或继续扩大替换表；前者会造成布局分歧，后者难以可靠覆盖动态文字和代码边界。消息表增加一次迁移成本，但可通过类型检查和逐页检查确认完整性。

### 3. 访客流程与信息层级

主页保留简短介绍，提供四个站内任务入口，将生成区域提前到主要内容前部；长篇展示和开发者文档放在核心任务之后。外部准备工具继续明确链接到原应用。每页显示一句任务说明、必要输入、结果和主操作，默认加载或生成现有有效配置。高级选项采用原生 `details`；如保留输出标签页，补全角色、选中状态、方向键和焦点控制。

| 页面 | 首次可见内容与主操作 | 按需展开内容 |
| --- | --- | --- |
| 首页占位图 | 预览、常见尺寸、配色、文字、复制图片链接、打开 SVG | 效果细调、速度、署名、HTML/CSS/Markdown/代理说明 |
| 转换器及定向页 | 当前来源、示例、预览、目标格式和复制 | 其他格式说明及 API 请求 |
| 配色 | 主题、色卡、复制单色和整组、刷新 | API 地址与开发者说明 |
| 颜色名称 | 搜索、数量、清除、色卡复制 | 数据来源说明 |
| 流动占位图 | 预设、配色、预览、复制图片链接 | 速度、文字与 API 说明 |

尺寸预设采用方形 800×800、卡片 800×400、横幅 1200×400，仍允许 50–4000 范围内编辑。基础配色输入明确接受 2–10 个六位 HEX，保留首页可省略 `#` 的兼容性；逐项校验，禁止静默删除非法颜色。数值越界、空输入及文本长度显示字段提示，不隐藏用户草稿。

转换器保留四种格式的编辑能力，将当前来源明确标示。定向页依据路径选择来源并优先排列目标结果；通用页默认 HEX，有保存状态时优先恢复状态。一个格式被编辑后，它成为来源，其余为计算结果；使用各格式示例可快速得到有效输入。尚未取得当前结果时，相应复制按钮停用。

配色主题显示本地化标签；整组复制输出逗号分隔 HEX，便于粘贴到占位图。刷新同一主题可能返回相同配色，按钮和说明不承诺随机变化。颜色名称按不区分大小写的标准名称或 HEX 子串过滤，保留 CSS 标识符并在提示中给出示例。

备选方案是仅翻译现有页面并增加长篇使用教程；它无法改善主操作位置和失败恢复。本设计采用统一信息层级，不要求读完说明才能使用。

### 4. URL 保存工具草稿，语言链接保留查询及片段

为每页定义序列化与校验逻辑，用 `URLSearchParams` 保存可共享的状态，以 `history.replaceState` 更新当前地址，避免每次输入产生历史记录。语言链接只替换已知语言前缀，保留查询和 hash，并在点击前同步最新草稿。基础链接在脚本不可用时仍能到达对应页面。

| 页面 | 页面查询参数 |
| --- | --- |
| 首页 | 保留 `w`、`h`、`effect`、`palette`、`speed`、`text`、`attribution` |
| 转换器 | `format`、`value` |
| 配色 | `theme` |
| 颜色名称 | `q` |
| 流动占位图 | `palette`、`speed`、`text` |

页面状态与外部 API 参数分别校验。无效但长度受限的原始输入可以保存并在目标语言中提示错误，不能直接发往 API。缺少参数使用默认值，未知枚举提示并提供恢复默认操作；既有 `attribution=false` 和 `0` 均恢复为关闭。URL 与自定义配色输入互相同步。参数长度按已知 API 上限及足够容纳错误修正的草稿上限限制，任意查询不作为 HTML 执行。片段定位保持同一区域，不保证翻译后精确像素位置。

备选方案为 localStorage；它不能通过共享链接复现状态，且会引入设备上的持续存储。URL 与当前浏览器状态满足本次需求；如果浏览器限制 history 操作，保留页面内输入并在切换前构造完整目标地址。

### 5. 草稿、有效参数与预览状态分离

共享逻辑区分当前草稿、经过校验的请求快照和最近成功结果。每次输入意图立即递增序号，包括延迟触发阶段；实际请求可取消时使用 `AbortController`，无论是否可取消都以序号判断响应是否有效。图片加载成功和失败也执行该判断。错误响应、无效数据和重试统一进入当前意图的状态，不覆盖新结果。

- 转换器和配色的当前结果必须在响应成功且结构合法后才可复制。保留的旧结果显示“上次结果”，不标为当前结果。
- 首页与流动图在参数校验成功时即可生成合法 URL；预览加载失败仍能复制该 URL或打开 SVG。旧图片如保留则标明为上次预览。
- 无效草稿阻止请求和当前输出复制，保留字段及上次预览；字段错误和网络错误分开呈现。
- 颜色名称加载完成后读取当前查询；失败重试不重置查询。数据结构先验证，错误响应不生成色卡。

备选方案只禁用加载中的输入；这会拖慢连续调整，还不能解决图片响应顺序。保留可编辑控件并保护提交结果，允许访客继续调整。

### 6. 共享复制与反馈

首页及工具使用同一复制行为：优先 `navigator.clipboard.writeText`，失败后尝试备用方法并检查返回值，只有明确成功才显示确认。全部失败时显示可聚焦、可选择的原文与手动复制提示；完成或关闭后恢复合理焦点。每个按钮维护独立操作序号与恢复计时，避免连续复制反馈错位。提示使用语言消息和适当的 live region，不仅变更颜色。

备选方案仅使用浏览器剪贴板接口；权限限制时用户缺少继续方式。备用方法保留兼容性，但不保证其成功，手动复制作为明确恢复路径。

### 7. 公开文档与搜索信息

现有根文档保持原地址及兼容内容。在文档模块增加日文正文/说明映射，仅在全球配置挂载三个 `/ja/` 文档，并在语言页面路由之前注册，避免与页面处理发生冲突。OpenAPI 共享结构与机器字段，只本地化 info、标签说明、operation 描述、参数说明等文字；文档中的示例、外部 API 路径和技能可识别的标识符保持有效。

SEO 的页面描述、面包屑及结构化文本使用消息表；Open Graph alternate 支持多语言列表。hreflang 继续包含两个部署的中文版本，新增全球 `ja` 并保持互相对应。两个 sitemap 与校验脚本从部署配置和现有页面清单生成，不按语言二选一；查询草稿不进入 canonical。全球列出 51 个语言页面，中国列出 17 个，文档通过页面入口发现，不混入 HTML 页数量。sitemap 修改时间对应实际发布版本。

备选方案为替换根文档内容；会影响已有使用者，故采用新增日文地址。文档响应类型保持 text/plain、Markdown 对应既有类型及 JSON。

### 8. 日文排版与可验证交互

共享样式增加日文字体回退（系统日文字体、Noto Sans JP、sans-serif）和合适行高；采用可换行的标签与自适应控件布局。360 像素视口无页面级横向溢出，代码容器独立滚动；所有语言应用相同的 44 像素触摸目标和可见焦点。菜单支持关闭与焦点恢复，字段具备描述/错误关联及 `aria-invalid`。

现有 Hono 请求测试覆盖 17×3 页面、文档和中国部署；增加针对客户端状态、序列化、复制失败和响应顺序的可控测试。测试不依赖外部 API 的随机性或真实权限。浏览器验收另行检查 360 像素与桌面、三语言、键盘以及错误恢复，不能用静态 HTML 检查代替交互验证。

备选方案只扩充页面文字断言；无法证明切换保留输入或失败后继续操作，因此同时验证客户端行为与浏览器流程。

## Risks / Trade-offs

- [迁移消息时遗漏动态文案] → 按页面列出静态、动态、ARIA 与输出说明清单，类型检查键完整性，逐页触发成功和失败状态检查。
- [URL 草稿与 API 参数混淆] → 分开序列化与契约校验；仅有效快照构造请求，测试无效条目、特殊字符和往返恢复。
- [日文翻译生硬或控制宽度增加] → 按访客任务使用简短用语，检查术语一致性与实际页面；保留标准技术名称，验证日文小屏幕布局。
- [公开链接包含自填文字] → 与现有首页参数行为一致，参数只保存工具输入，不新增其他个人数据；反馈和使用说明不宣称私密存储。
- [外部 API 慢或不可用] → 保留当前输入与标明来源的有效结果，提供页面内重试，合法 SVG 链接保持可用。
- [本地检查无法证明线上搜索收录或实际需求] → 本次验收限于路由、元信息及操作正确性；发布后的收录与访问变化单独观察。

## Migration Plan

1. 先完成语言基础和消息迁移，再应用工具状态、复制与异步管理；全程保留现有地址和 API 契约。
2. 完成日文公开文档与 SEO，运行类型检查、测试、Worker dry-run 和中国站静态构建，检查全球/中国页面矩阵。
3. 在本地预览完成浏览器交互验收并记录结果。规划本身不部署；实际发布在获授权的实现阶段执行。
4. 如需撤回，回退本次代码版本和对应构建产物；无数据库迁移。若日文地址已经发布，撤回时为已公开的日文地址提供明确的临时跳转到对应英文内容，恢复版本后撤销跳转，避免长期无效链接。
